## 7. Security findings (why nothing from the old install is reused)

Static analysis only (files were read, never executed). The main payload lived at
`/home/itsredpr/wp-sys-cache.php`, outside `public_html`, which means the cPanel account
itself was compromised, not only WordPress.

| Severity | Location | Finding |
|---|---|---|
| Critical | `php.ini`, `.user.ini` | `auto_prepend_file` → external payload, runs before every PHP request |
| Critical | `wp-content/sunrise.php` | `WPCL_SUNRISE_V1` include of the same payload (second persistence path) |
| Critical | `wp-content/mu-plugins/.d84d92c5-*.tmp` (5) + `uc-guard.php` | Hidden encrypted blobs (~88 KB), likely a self-restoring loader |
| High | `wp-content/plugins/gallery_1773853248/` | Cloned "EPS 301 Redirects" plugin with `functlons.php` and `wf-flyout/icons/top-1773853249.php` (2026-03-18) |
| High | `wp-content/plugins/updatecore/` | Fake "updatecore" / "wp-cleanup-tool" plugin (2026-07) |
| High | Homepage HTML | ~25 injected casino spam links (SEO spam) |
| Medium | `ebnuw.php`, `koxkl.php`, `najld.php` (root) | Random-named droppers (2026-03), now 0 bytes |
| Medium | WP File Manager Pro | Plugin with a history of critical vulnerabilities; suspected entry point (unproven) |
| High | `wp-config.php` inside the Drive zip | Contains the old DB name and password; restrict the Drive share |

Follow-ups outside the codebase: restrict/delete the Drive zip, check Google Search Console
(Security issues, Manual actions), audit GTM `GTM-K54X9Q7C` access, confirm the old hosting
account `itsredpr` is closed.
